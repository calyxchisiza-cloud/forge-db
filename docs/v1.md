# ForgeDB v1

v1 is one database in one file, used by one process. `Create` makes the file. `Open` reads it. There is no `CREATE DATABASE` statement.

## Statements

A statement uses literal values. It does not evaluate expressions. Keywords ignore case. Identifiers keep the spelling they were given.

| Statement | Rule |
| --- | --- |
| `CREATE TABLE` | `INTEGER` and `TEXT` columns. One of them is the primary key. |
| `INSERT` | Every column is supplied. A primary key is stored once. |
| `SELECT` | A star or a column list, then `WHERE` comparisons joined by `AND`. `ORDER BY` names one column and sorts in memory, then `LIMIT` keeps a prefix. Without `ORDER BY`, row order is undefined. |
| `UPDATE` | `SET` assigns literals. |
| `DELETE` | Removes the matching rows. The empty slot stays, so other row identifiers do not move. |
| `BEGIN`, `COMMIT`, `ROLLBACK` | Group statements. Outside `BEGIN`, one statement commits on success. |

A comparison with `NULL` is not true. A failed statement rolls the whole transaction back. A row must fit in one page. A primary-key lookup uses the B+Tree. Any other filter reads the table.

## Readers and writers

Several queries run at once. One writer waits for them, then holds the database until commit or rollback. Readers that arrive during that wait see the last committed pages, not the open transaction. A failed statement releases the writer.

## Durability

Commit appends a full image of each changed page and a commit record to `path.wal`, and syncs that log before it returns. Those pages reach the database file at checkpoint, when a dirty page is evicted, or the next time the file is opened. Recovery replays a committed transaction, skips a page whose sequence number is already current, ignores a torn final record, and stops when a bad checksum has more bytes after it. A transaction with no commit record is discarded.

## Not built

v1 does not have defaults, joins, subqueries, aggregates, or foreign keys. It does not keep multiple versions of a row. Undo, a doublewrite buffer, a change buffer, and an adaptive hash are InnoDB mechanisms this database does not include.

## Shell

```
go run ./cmd/shell -db forge.db
```

A missing file is created. Each line is one statement, and a semicolon may end the line. `.quit` or the end of input closes the database. A query prints the columns and `(N rows)`. Any other statement prints `changed N`. A bad line is reported and the next line still runs.

## Benchmarks

```
go test -bench=. -benchmem .
```

`BenchmarkInsert`, `BenchmarkSelect`, and `BenchmarkUpdate` time the public statements. Insert and update commit on each call, so their time includes the log sync. Read the numbers on the machine you care about before describing a rate.

## Viewer

```
go run ./cmd/ui -db forge.db
```

Open `http://127.0.0.1:8091`. The page lists every database file in the folder. Opening one shows its tables, the columns and primary key of each, and the rows. A row can be edited or deleted. ForgeDB does not store foreign keys, so the structure view does not draw links between tables. The statement field is still there for one SQL statement. `go run ./cmd/ui -db forge.db` opens that file first.
